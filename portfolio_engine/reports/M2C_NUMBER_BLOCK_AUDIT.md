## 2. Descriptive diagnostics of the fields (`m2c_number_block_diagnostics.json`; no batching performed)
* 39,874 parents; order number unique per date and constant within a parent; app key last-6 `632469` (38,770 parents) and `F88187` (1,104); full key is 32 characters (TP-01 and TP-02 used only the last 6).
* **602 blocks** per `(date, app key)` (530 jumps > 500 plus the 72 `(date, app key)` groups; reproduces DAT-12's 602 exactly).
* Consecutive order-number differences inside a block (all orders): median 2, p75 8, p90 24, p95 45, p99 145; **88.2 % ≤ 20**. Across blocks (all jumps) 530 jumps exceed 500.
* Adjacent **closing** parents inside one block (16,817 closing parents; 16,290 adjacent pairs): number difference median 2, p75 13, p90 48; **80.5 % ≤ 20**.
* Pair co-occurrence of the two proximity notions — **diagnostic only, and not the C1 definition**: pairs adjacent in **order-number** order within a block, time measured as |Δ first-fill| ≤ 10 s (C1 uses time-order adjacency and a signed gap); **these are pairs, not batches**: number ≤ 20 **and** first-fill gap ≤ 10 s: 10,164; number ≤ 20 only: 2,954; first-fill ≤ 10 s only: 558; neither: 2,614.
* Order numbers are monotone in parent first-fill time inside a block except for **0.73 %** adjacent inversions, measured as: parents sorted by order number within a block, share of adjacent pairs whose first-fill time decreases (DAT-12's 0.74 % was measured at fill level; an alternative definition by the independent reviewer gave 0.741 %: both are ≈ 0.7 %).

## 3. Competing interpretations (none established)
| | Exact proposed rule | Supporting evidence | Contradicting / missing evidence | Expected impact on membership | False-grouping risk |
|---|---|---|---|---|---|

**Information still missing:** the reason 20 was chosen (no derivation exists), whether "consecutive" means closing-only or all orders, whether a time limit was intended, whether other clients' orders interleave the numbering, and the meaning of the blocks (gateways / sessions — DAT-12 itself says the meaning is not established).

## 4. Recommendation
Keep `CB_NUMBER_BLOCK_V1` **unimplemented**. To proceed the reviewer must choose among N1–N3 (or supply the original intent); my recommendation is **N1 without a time limit as the literal reading, reported next to N3 only if a time limit is explicitly approved**, because the registered text mentions neither. Whichever is chosen must carry its own convention token (`CB_NUMBER_BLOCK_V1_<variant>`), report chain durations, and never be merged with C1/C2.
