# Environment and reproducibility statement

Closes the documentation part of M2-F defect E-D09 (dependencies unpinned). Machine-readable lock: [`../requirements.lock.txt`](../requirements.lock.txt). It is checked by `tests/test_environment_lock.py`
(fails if the file is missing or if a third-party package imported by the project's Python files has no `==` pin; version differences between the lock and the running interpreter are REPORTED, never failed).

## Reference environment (where the delivered outputs and all test results come from)

| Component | Version |
|---|---|
| Python | 3.13.18 |
| numpy / pandas / pyarrow | 2.5.3 / 3.0.5 / 26.0.1 |
| matplotlib | 3.11.2 |
| pytest | 9.2.0 |
| g++ / cmake | 13.3.0 (Ubuntu 13.3.0-6ubuntu2~24.04.1) / 3.28.3 |

## What is asserted

* **Python engine core is standard-library only** (ledger, replay, lineage, lineage_set, invariants, closing_batches, wing_body, cases, tsvio, provenance, cli, the synthetic generators): no third-party version can change a replay result. Verified by an AST scan of the imports (M2-F track E).
* **Data outputs** (`.tsv`, `.tsv.gz`, `.csv`, `.json` payloads) of the M2-C/M2-D/M2-E generators were regenerated byte-identical (modulo runtime metadata) under Python 3.11, 3.12 and 3.13 and under different `TZ`, `LC_ALL`, working directory and `PYTHONHASHSEED` settings (M2-F audit, one machine). `coverage.json` key order was the one exception and is fixed for future runs (E-D01; the delivered file's byte order is reproduced).
* **Same stack, same bytes**: with the reference environment above the baseline scenario reproduces every delivered generated file (`tests/test_scenario.py`, slow), including the matplotlib PNGs.
* The C++ core and the Python engine agree byte-for-byte on the tested domain (parity tests); that is cross-language consistency of one specification, not independent validation.

## What is NOT asserted

* **No guarantee under other versions.** pandas (reading the TP-01 parquet ledger, grouping), pyarrow (parquet decoding) and matplotlib (**PNG bytes**, which depend on the matplotlib/freetype/pillow stack) were verified only for the versions above. A different version may change input handling or PNG bytes (SUSPECTED, not measured). Data CSV/TSV hashes are the stable evidence; PNG hashes in the figure manifests are informational.
* **No hash of the operating system, libc, freetype build or the C++ binary** is recorded in any manifest. `pe_replay` is built locally; its identity is not stamped into run manifests.
* **Provenance heads do not identify the generating code** (E-D02): `generated_at_head` in the delivered manifests is the git HEAD at generation time and may predate or differ from the committed outputs. `provenance.code_fingerprint(pe_root)` (sha256 over `python/pe/**/*.py` and `tools/*.py`) now exists to identify code; stamping it into manifests is proposed for SCENARIO manifests and not done in delivered manifests.
* **`run_id` of `pe.cli` includes the git HEAD** of the repository holding the events file (or `UNAVAILABLE`), so it changes with every commit even for identical inputs (documented by `tests/test_cli_and_provenance.py::test_run_id_depends_on_git_head_of_the_events_directory`).
* **Locale**: outputs were verified under `C`, `C.UTF-8`; an ASCII-only locale makes some writers fail (E-D04, open); `en_US` was not installed and is NOT VERIFIED. Windows newline handling NOT VERIFIED.
* **`market_data`** (tools/select_demo_cycles.py) is an external module and is not pinned or tested; raw 1-minute option bars are absent from this repository.
* The lock lists the environment as installed; it is not a hash-locked, platform-independent resolution (`pip install` from it on another OS/architecture may resolve different wheels).
