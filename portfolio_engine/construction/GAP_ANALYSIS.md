# Requirements-to-implementation matrix (written before any new code)

Inspected: delivered `Algo8_M2_Delivery.zip` (133 files), `portfolio_engine/python/pe`, `portfolio_engine/cpp`, `tests/test_accounting.py::test_cut_reentry_195_accounting_follows_actual_fills_only`.
Interfaces found: Python `pe.ledger.PortfolioState.apply_fill(fill)` and C++ `pe::PortfolioState::apply_fill(fill)` are the only places where inventory changes (their own docstring says proposals never call them). Python and C++ already share the fill/instrument types and the TSV formats.
Design consequence: new plugins propose actions; an execution layer turns accepted actions into explicit synthetic fills and calls the existing `apply_fill`. No second accounting engine and no second inventory.
